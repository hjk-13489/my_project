# Epic 2 Context: 商品发布与浏览（listings）

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

让已认证的卖家把闲置（字段 + 图片）发布进平台、先经审核才对外上架，买家由此能浏览、搜索、筛选并查看已上架商品的详情，作为协商与下单的入口。它守住「同校可信」的关键门控——发布即上架会架空管理员审核，因此对外可见性必须由审核状态驱动；同时这是整条交易闭环（发布 → 审核 → 浏览 → 协商 → 下单）得以启动的前提。

## Stories

- Story 2.1: 发布商品（含图片上传）
- Story 2.2: 商品状态流转：待审核→上架/驳回
- Story 2.3: 驳回通知与重新提交
- Story 2.4: 查看我的发布
- Story 2.5: 商品列表浏览（仅上架）
- Story 2.6: 关键词搜索
- Story 2.7: 分类/价格/成色筛选
- Story 2.8: 商品详情页

## Requirements & Constraints

- 发布资格：仅已登录且已认证的卖家可提交；所有写操作需登录鉴权，用户只能读写本人数据。
- 商品字段：标题、描述、价格、成色、分类必填；价格为数字且 > 0；分类限「教材/日用品/电子数码/其他」，成色限「全新/良好/中等」，越界值被拒绝。
- 图片：每商品 ≥ 1 张，仅 JPEG/PNG，单图 ≤ 5MB，存本地 `media/`。
- 先审后上架：提交后为待审核（`pending`）不对外可见，审核通过（`approved`）才可被命中，`rejected`/`offline` 不可见；列表、搜索、筛选、详情的查询必须在服务端强制过滤 `approved`，不得靠前端隐藏；非上架商品详情页返回 404。
- 驳回闭环：驳回理由送达卖家「我的消息」，卖家可修改原商品重提，状态回到 `pending`。
- 「我的发布」：按状态展示本人各商品，仅本人数据。
- 列表与检索：列表卡片含缩略图/标题/价格/成色；关键词匹配标题或描述；分类/价格区间/成色可组合筛选，结果须满足全部条件且仅为上架商品。
- 详情页：展示全部图片与字段、卖家昵称 + 认证状态，提供「联系卖家」「立即购买」入口；不暴露卖家 QQ/微信（联系方式仅对已下单买家可见）。
- 性能（演示环境）：列表/搜索响应 ≤ 1s（P95），普通页面首屏 ≤ 2s；目标浏览器最新版 Chrome/Edge。

## Technical Decisions

- **归属与分层**：落在 `listings` app；分层单体 Django MTV，依赖单向（模板 → 视图 → 服务/表单 → 模型 → DB），下层禁止反向 import 上层；业务规则（尤其可见性门控）下沉到 Models/Services，视图只做请求编排。
- **唯一定义**：商品可见性逻辑归 `listings` 唯一定义（如 manager/queryset 的 `visible()`），管理员后台复用而非另写一套过滤；同层跨 app import 允许。
- **状态驱动可见性**：可见性由 `status` 字段驱动（`pending`/`approved`/`rejected`/`offline`），所有对外查询统一强制 `status=approved`。
- **存储**：关系型数据库 + Django ORM，migrations 管理 schema；开发/演示用 SQLite。
- **字段约定**：价格 `DecimalField(10,2)`；成色/分类/状态用 `choices` 枚举；主键自增 int；时间 UTC（`USE_TZ=True`）；错误统一为表单错误或 JSON。
- **图片**：Pillow 校验 JPEG/PNG 并缩略，存本地 `media/` 由 Django 静态媒体服务返回，不引入云对象存储。
- **授权**：服务端强制（登录装饰器 + 查询过滤），角色 `student`/`admin`；禁止仅前端隐藏式伪权限。
- **命名**：app 复数小写、Model 单数 CamelCase、字段 snake_case、URL 语义命名（如 `/listings/<id>/`）；目录结构以既有脚手架为准。

## UX & Interaction Patterns

- 卖家流程：发布表单（填字段 + 传图）→ 提交进入待审核 → 审核结果经「我的消息」通知；被驳回则在「我的消息」看到理由、修改后重提。
- 买家流程：列表 / 搜索 / 组合筛选 → 商品详情页 → 「联系卖家」进聊天、「立即购买」进下单；列表卡片仅呈现缩略图/标题/价格/成色。
- 个人中心「我的发布」按状态呈现本人商品进度；全部为服务端渲染网页（Bootstrap），仅桌面 Chrome/Edge，无移动端、无实时推送。

## Cross-Story Dependencies

- 内部：2.1 产出的商品与 `pending` 状态是 2.2/2.3/2.4 的前提；2.2 的 `approved` 是 2.5/2.6/2.7/2.8 能被命中的前提，所有对外可见查询共用同一套 `approved` 过滤。
- 依赖 Epic 1：发布需账号已认证且已登录；个人中心「我的发布」入口、详情页卖家认证标识均由 `accounts` 提供。
- 依赖 Epic 5：审核通过/驳回/下架动作由管理员后台触发，本史诗只消费由此产生的 `status`，不实现审核界面。
- 对外输出：详情页「联系卖家」交给 Epic 3（聊天）、「立即购买」交给 Epic 4（下单），本史诗只需就位并可跳转。
